GitHub Pages にデプロイして、Space Quiz を誰でも利用できるようにしましょう。Copilot はワークフローを準備してデプロイを案内できますが、変更をレビューし、サイトが公開されたことを確認するのはあなたの責任です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages デプロイの設定を依頼します。
- マージする前にワークフローとプルリクエストをレビューします。
- デプロイの進行を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、誰もが簡単に試せるようにする必要があります。単一ファイルのサイトを GitHub Pages で公開すれば、サーバーやランタイム依存関係を追加せずに、公開 URL から利用できるようになります。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プルリクエストの作成によって、コードがコミットおよびプッシュされることがあります。プロンプトを送る前に、承認設定と対象リポジトリを確認してください。**すべて承認**に設定している場合、別途確認が求められるとは限りません。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリに GitHub Pages デプロイを準備してください。必要であればサイトをビルドし、既定のブランチに変更が反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README がまだなければ、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更を含むプルリクエストを作成し、そのリンクと必要な Pages 設定や権限を報告してください。マージ、自動マージの有効化、Pages 設定の変更、デプロイは行わないでください。レビューを待って停止してください。
```

## ワークフローとプルリクエストをレビューする

1. リポジトリに README がない場合に限り、README が追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限など、プルリクエストの変更をレビューします。
3. ワークフローが、マージされていないプルリクエストではなく既定のブランチからデプロイすることを確認します。
4. 必要な修正を依頼し、更新後の差分をレビューします。マージを許可する前に、必要なプルリクエストのチェックがすべて成功するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトを送ると、レビュー済みプルリクエストのマージ、リポジトリの Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、対象のリポジトリとプルリクエストを確認してから送信してください。承認設定によっては、これらの操作が追加確認なしで実行されることがあります。

`<PR_NUMBER>` をレビューしたプルリクエスト番号に置き換えてから、この別のプロンプトを送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使う GitHub Pages を有効にし、必要なチェックが成功した場合に限ってプルリクエストをマージし、デプロイが成功するまで状況を確認してください。公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージの権限がない場合は、私が承認または実行する必要がある内容を正確に伝えてください。サイトが公開されるまでは成功と報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages を有効にできない場合やプルリクエストをマージできない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまでは、作業が完了したと見なさないでください。
