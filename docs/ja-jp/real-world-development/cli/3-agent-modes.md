最初は小さな機能を追加しました。しかし、より大きな変更には、より確かなプロセスが必要です。GitHub Copilot CLI は組織の既存のフローに沿って動作し、適切な方法で必要なものを作るよう支援します。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを進めます。まず課題から新機能を作り、コードの妥当性と機能の動作を確認し、最後にプロジェクトへ正常にマージします。

> [!NOTE]
> 機能開発を続ける間は、同じ会話とブランチを使います。通常は、扱うファイルの種類ごとに異なるブランチや PR を使いますが、ここでは基本概念に集中するために簡略化します。

まず、このレッスンでは次のことを行います。

- GitHub の課題から新しい Copilot 会話を始めます。
- Plan モードで要件を決めます。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルを調整し、MCP による検証を追加して、QA エージェントを作成し、機能 PR を開きます。

## シナリオ

Tailspin Toys のカタログが増えているため、訪問者がカテゴリやパブリッシャーでゲームを絞り込めるようにする必要があります。バックログの課題には機能の概要が記載されていますが、カテゴリを組み合わせる方法など、実装前に合意が必要な詳細もあります。Plan モードで決定し、範囲を限定した実装を Autopilot に許可します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、より重要になります。多くの開発者は、次のような流れで作業しています。

1. 実装内容を記述した課題を作成します。
2. 実装する内容の計画を立てます。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 詳細な進め方はチームや組織によって異なりますが、ほとんどの場合は上記の流れを調整したものです。

この標準的な進め方を守れば、AI が生成したコードが要件を満たし、手作業で作成したコードと同じ確認プロセスを経ることを保証できます。

## 会話モード

**会話モード**は、エージェントにどれだけの自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive:** エージェントと一緒に作業します。エージェントは変更を提案し、あなたの入力を待ってから続行します。
- **Plan:** エージェントはまず計画を作成し、プロジェクトファイルの編集は行いません。
- **Autopilot:** エージェントはコードの作成、テストの実行、反復を自律的に行い、タスクの完了を目指します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## 課題から始める

フィルターの作業を始める前に Codespace に戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespace に戻ります。停止中の場合は、再起動してから続行します。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての課題を表示します。
8. 矢印キーを使って **Allow users to filter games by category and publisher** というタイトルの課題を選択します。
9. <kbd>C</kbd> を押して課題をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または類似の番号) が表示されます。`#` を使うと、GitHub 上の課題やプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てると、機能やタスクを Copilot に依頼する前に実装方針を決められます。複雑な作業では、時間をかけて計画するのが効果的です。Plan モードに切り替えて、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した課題への参照の後に、次のプロンプトを入力します。

   ```plaintext
   この機能を実装する計画を作成してください。
   ```

Copilot はプロジェクトを調査し、最適な方法を検討して計画を作成します。

3. フィルター機能の動作について質問された場合は、希望に応じて回答します。正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を上下にスクロールして確認します。
6. 自分の決定と合っていない部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画ができてレビューも終わったので、実装に進みましょう。Autopilot を使って Copilot に作業を任せます。

Autopilot では、Copilot が完了したと判断するまで問題に取り組み、反復できます。

1. **Accept plan and build on autopilot (recommended)** またはインストール済みバージョンで同等の名前が付いた項目を選択します。
2. プロンプトの下にあるモード表示が **Autopilot** であることを確認します。
3. Copilot が合意済みの計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、実装がすぐに始まることがあります。先に計画を確認してください。Copilot が依存関係の不足やポートの競合を報告した場合は、チェック完了と見なす前にセットアップの問題を解決してください。

## 実装をレビューして検証する

他のコードと同じように、生成されたコードもマージする前にレビューする必要があります。コードを確認し、サイトを実行して動作も確かめましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルターの実装とテストを調べます。
3. 結果を課題と計画中の決定に照らし合わせます。
4. コードのレビューが終わったら、<kbd>Esc</kbd> を押して差分表示を終了します。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新機能を試す

コードは問題なさそうですが、実際に動くでしょうか。以前と同じようにアプリを起動し、Codespaces の転送ポートからサイトを開きましょう。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   ブラウザーでフィルター機能を試せるよう、アプリを起動してください。URL を教え、サーバーを起動したままにしてください。
   ```

2. Codespaces がポート `4321` を使用可能と表示したら、**Open in Browser** を選択します。
3. 計画で合意したカテゴリ、パブリッシャー、および組み合わせで絞り込みます。
4. リセットと結果が空の場合の動作が、課題と決定内容に一致することを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

さまざまな会話モードを使って、機能を作成しレビューしました。このレッスンでは、次のことを行いました。

- GitHub の課題から新しい Copilot 会話を始めました。
- Plan モードで要件を決めました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動検証しました。
