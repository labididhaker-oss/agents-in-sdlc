`quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザー上のフィルター機能を確認しました。次は、これらの機能を明確な QA プロセスを持つカスタムエージェントにまとめます。

このレッスンでは、次のことを行います。

- カスタムエージェントと指示、スキル、MCP ツールの連携を確認します。
- 再利用できる quality assurance プロファイルを作成して調べます。
- QA エージェントを選択し、フィルターの課題に照らし合わせて結果を確認します。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト範囲、ブラウザーでの動作を一貫して確認したいと考えています。カスタムエージェントを使うと QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の専門的な役割です。プロファイルにはエージェントの目的、指示、利用できるツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明し、`quality-checks` スキルは繰り返し実行できるチェックをまとめ、Playwright MCP はブラウザーツールを提供します。QA プロファイルは、それらを使って要件を評価し、結果を報告する方法を Copilot に伝えます。これらを置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、再利用可能な QA プロファイルを作成するよう Copilot に依頼します。このプロファイルでは、QA が実行するチェックと、その作業の境界の両方を定義します。

1. Codespace に戻り、フィルターの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、新しいカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を課題と合意済みの要件に照らし合わせて確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、テスト範囲が不足している場合はテストを追加してください。

   各要件について、根拠を示しながら pass、fail、blocked のいずれかで報告してください。実装コードを変更する前には必ず確認を求め、変更をコミットしたりプルリクエストを作成したりしてはいけません。

   まずはレビューできるよう、プロファイルだけを作成してください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA ワークフローと境界を反映したことを確認します。確認を依頼しただけなのに、不完全または広範すぎるエージェントが機能を変更するのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は任意ですが、含めると表示名が明確になります。
3. プロファイルの指示を読み、QA が要件を起点とし、リポジトリの指示に従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. QA が根拠を示して報告し、実装コードを変更する前に確認を求め、変更をコミットしたりプルリクエストを作成したりしないことを確認します。
5. これらの責務や境界が不足している場合は、続行する前に既定のエージェントに修正を依頼します。

## 課題に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じフィルターの会話を再開し、QA を選択すると、それまでの課題と計画内容を使えます。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成した直後は、利用可能なエージェント一覧に表示されない場合があります。上記のコマンドで有効にできます。

2. 次のプロンプトで QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   課題と計画で決めた内容に照らし合わせて、フィルター機能をレビューしてください。PR を作成できる状態ですか?
   ```

3. QA エージェントが作業を開始します。
4. 完了したら、レポートを確認します。

## まとめと次のステップ

ワークフローに再利用可能な専門的役割を追加し、その作業をレビューしました。このレッスンでは、次のことを行いました。

- カスタムエージェントと指示、スキル、MCP ツールの連携を確認しました。
- 再利用できる quality assurance プロファイルを作成して調べました。
- QA エージェントを選択し、フィルターの課題に照らし合わせて結果を確認しました。

実装、スキルの更新、QA プロファイル、テスト、検証レポートが揃いました。次は、それらを機能 PR にまとめ、Agent Merge を使います。
