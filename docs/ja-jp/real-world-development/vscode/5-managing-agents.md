GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を採用または却下できます。エディターを離れずに追加のプロンプトを送り、作業を改善したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- エージェントのセッション中にライトモードの切り替えを追加するよう依頼する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を始める代わりに、既存のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが行う各手順を確認できます。調査するファイル、実行するコマンド、提案する編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作を含めてチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取り、編集、実行を求められたターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を取り消して、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、セッション中にエージェントが変更したファイルの一覧を確認することもできます。

> [!NOTE]
> ツール呼び出しで許可を求められる場合 (たとえば、ターミナルコマンドを実行する場合)、エージェントは一時停止して **Allow** を表示します。許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライトモードを追加するよう依頼する

ハイコントラストモードが実装されたので、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けることで、エージェントは前の作業からコンテキストを引き継ぎます。変更したコンポーネント、使用したスタイル、設定したローカルストレージのパターンなどが保持されます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    よくできました。ハイコントラストの切り替えと並べて、ライトモードの切り替えも追加してください。ライトモードも同じパターンに従い、ローカルストレージで設定を維持し、同じ UI 領域から操作できるようにしてください。ユーザーはハイコントラストモードとライトモードを個別に有効化できる必要があります。
    ```

2. エージェントはすでに行った変更を調べ、ライトモードを追加する提案をします。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合 (たとえば、好みに合わない方法で切り替え UI をリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで作業を止め、補足プロンプトを送ります。

> [!TIP]
> 実行中のセッションに指示を加えるほうが、最初からやり直すより早く済みます。追加プロンプトで、調整を依頼します (「CSS を簡略化し、セレクターの重複ではなく CSS 変数を使う」)、方針を修正します (「3 つ目の切り替えは追加せず、既存の設定パネルにライトモードを組み込む」)、範囲を拡張します (「両方の切り替えにキーボードショートカットも追加する」)。

## 変更されたファイルを確認する

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージでの設定維持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、実行中のセッションを監視して誘導しました。ファイル編集を確認して採用または却下し、コンテキストを保ったまま追加プロンプトを送信して作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または却下する。
- 追加プロンプトで実行中のセッションを誘導する。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが行った変更をレビューします。
