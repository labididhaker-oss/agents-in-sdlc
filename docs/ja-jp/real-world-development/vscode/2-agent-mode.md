アプリの小さな更新でも、通常は複数のファイルを変更し、テストなどを実行する必要があります。開発者は、関連するファイルを探し、変更を行い、テストを実行し、問題を調査して、見落としたファイルを見つけ、さらに変更を加えます。作業は次々に続きます。

ここで役立つのが Copilot Agent Mode です。

Copilot Agent Mode は、IDE 内でより自律的に作業します。開発者と同じように、まず既存のプロジェクト構成を調べ、必要な変更を行い、テストなどのタスクを実行し、見つかった問題を自動的に修正します。Agent Mode を使って、サイトに新しい機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、agent mode と cloud agent は異なる用途向けに作られています。Agent mode は IDE 内で動作し、すばやいフィードバックと対話を可能にします。Cloud agent はチームメンバーのように非同期で作業し、課題やプルリクエストを通じてやりとりします。

この演習では、次のことを学びます。

- Copilot Agent Mode がプロジェクトを調べ、関連ファイルを特定し、複数ファイルにまたがる変更を行う方法。
- GitHub Copilot Agent Mode で UI とデータレイヤーに新機能を実装する方法。
- Copilot Agent Mode が生成した変更とテストを、コードベースにマージする前にレビューする方法。

## シナリオ

ゲームの一覧が増えているため、ユーザーがカテゴリやパブリッシャーで絞り込めるようにします。前の演習ではすでにパブリッシャーヘルパーを追加しました。ここでは、Copilot Agent Mode を使って残りのデータレイヤー、UI、テストを仕上げます。

## Tailspin Toys の Web サイトを実行する

変更を加える前に、Tailspin Toys の Web サイトを確認し、現在の機能を把握しましょう。

この Web サイトは、開発者向けテーマを採用したボードゲームのクラウドファンディングプラットフォームです。ゲームの一覧と詳細を表示します。これは単一の Astro アプリで、ビルド時にページを静的 HTML として生成します。ページは、Drizzle ORM を通じて frontmatter からローカルの SQLite データベースを直接参照します。別個のバックエンド API やクライアントサイド UI フレームワークはありません。再利用可能なデータアクセスヘルパーは `src/lib/` にあり、対話機能は標準の DOM API を使った、小さく範囲を限定した Astro `<script>` で追加します。

### Web サイトを起動する

Web サイトを簡単に実行できるように、単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。次の手順で GitHub Codespace から起動します。

1. Codespace に戻ります。前の演習の後であれば、`main` にいるはずです。
2. Codespace 内で <kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押して、新しいターミナルを開きます。
3. フィルター作業用のブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーが起動すると、次のような URL を含むメッセージが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くよう促すダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルの Astro サーバーアドレス `http://localhost:4321` を、<kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押しながら選択して、Web サイトを開きます。

> [!NOTE]
> Codespace を使っている場合、Codespace のターミナルで localhost の URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` にリダイレクトされます。これは、Web サーバーをホストしている Codespace へのプライベートトンネルです。

### Web サイトを確認する

Web サイトが起動したら、機能を確認します。主な機能は次のとおりです。

- **ホームページ:** ボードゲームの一覧と、タイトル、画像、説明を表示します。
- **ゲーム詳細ページ:** ゲームを選択すると、タイトル、説明、パブリッシャー、カテゴリなどの情報を掲載した詳細ページを表示します。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 次の演習を始める前に Codespace に戻り、Copilot Chat パネルを開き、**New Chat** を選択して新しい会話を始めます。モードとモデルの選択は演習によって異なります。必要な場合は、各手順で説明します。

Web サイトの最初の実装は動作しますが、新しい機能で強化したいと考えています。まずバックログを確認しましょう。テンプレートからプロジェクトを作成した際に、GitHub Copilot がバックログの課題も自動で作成しました。それらの一覧を Copilot に表示してもらいます。

1. Chat ビューのエージェント選択メニューから **Agent** を選択します。**Agent** エージェントは、自律的に計画して複数ファイルを変更し、ターミナルコマンドを実行して、ツールを呼び出します。

   ![Chat ビューでエージェントを選択する画面](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデルの一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者は、特定のモデルを推奨しているわけではありません。ワークショップの作成時に Claude Sonnet 4.5 を使ったため、手順に含めています。コードの提案に一貫性を持たせ、操作を分かりやすくするためです。ただし、大規模言語モデル (LLM) の出力は確率的に変わるため、ワークショップに記載したものと異なる提案が表示されることがあります。これは通常の動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が異なる MCP コマンドを使う場合がありますが、タスク自体は完了できるはずです。

3. 次のプロンプトを Copilot に送信して、バックログの課題を確認します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。ユーザーに最も役立つ課題を優先するよう支援してください。
   ```

4. **Continue** を選択し、すべての課題を一覧表示するコマンドを実行します。
5. 生成された課題の一覧を確認します。

Copilot は、ユーザーに最も役立つと考える順に課題を並べてくれます。

## 指示ファイルを確認する

エージェントにコード生成を依頼する前に、作業のコンテキストを Copilot に提供する指示ファイルを確認しましょう。Web サイトに機能を追加する際の方針が記載された [ユーザーインターフェイス (UI)](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md) ファイルを使います。

1. Codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能を追加する際の全般的なガイダンスを確認します。次の内容が含まれます。
   - アーキテクチャの概要。
   - コンポーネントの設計、テスト容易性、アクセシビリティの原則。
   - Astro、Tailwind CSS、Drizzle など、ファイル形式に応じた指示へのリンク。

> [!TIP]
> 指示ファイルから他の指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルからの相対パスです。指示を再利用したり、大きなファイルを小さく分けたり、Copilot が参考にできる例やテンプレートを示したりできます。

## フィルター機能を実装する

フィルター機能を完成させるには、少なくとも次の 3 つの変更が必要です。

- データレイヤー (`src/lib/`) に残りのフィルター処理を追加または調整する。
- フィルターの動作に対するテストを追加または更新する。
- ゲーム一覧ページを更新し、フィルター UI を追加する。

また、コードベースにマージする前にテストを実行し、成功する必要があります。Copilot Agent Mode にこれらの作業を依頼できます。機能を追加しましょう。

1. 現在の Copilot 会話を続けるか、**New Chat** を選択して新しい会話を始めます。
2. **Add Context**、**Instructions**、**ui** の順に選択して、指示ファイルを追加します。

   ![UI 指示ファイルを選択する例](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント選択メニューで、引き続き **Agent** が選択されていることを確認します。

   ![Chat ビューでエージェントを選択する画面](../../../_images/shared-chat-mode-selector.png)

4. モデルが引き続き **Claude Sonnet 4.5** であることを確認します。
5. バックログの関連課題に基づいて機能を実装するよう、次のプロンプトで Copilot に依頼します。

   ```plaintext
   バックログの関連 GitHub 課題の要件に基づいて、サイトにパブリッシャーとカテゴリで絞り込む機能を追加してください。前の演習ですでにパブリッシャーヘルパーを作成しているため、必要に応じてその作業を維持・改善しながら、残りのデータレイヤー、UI、テストを完成させてください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに起動しているため、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、機能に関連するファイルを見つけます。データレイヤーのヘルパー、UI、テストを探してファイルを変更し、テストを実行します。

   ![Copilot がプロジェクトファイルを調べている画面](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの編集、テストの実行など、複数の作業を行います。タスクやコードベースの複雑さによっては、数分かかることがあります。その間、コードエディターに **Keep** と **Undo** ボタンが表示される場合があります。作業が終わると、すべての変更に対する **Keep** または **Undo** が表示されるため、作業中に選択する必要はありません。

7. Copilot の確認に応じて **Continue** を選択し、テストを実行します。

   ![テスト実行の確認を求める Copilot Chat のダイアログ](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に一時停止したり、テストが失敗したりすることがあります。問題ありません。Copilot は、エラーが見つからなくなるまでコード生成とテストを繰り返します。

   ![Copilot Agent Mode のチャットセッションが完了した画面](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot や他の AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを起動したブラウザーに戻り、新しい機能を確認します。
11. すべてが動作することを確認し、コードのレビューを終えたら、Copilot Chat ウィンドウで **Keep** を選択します。

### 追加の探索演習 - ページングを実装する

ゲームの一覧が増えると、ページングが必要になります。この演習で学んだことを使い、Copilot にページングを実装するよう依頼します。コードを作成する際は、次の点を検討してください。

- 既存の指示ファイルを使うなど、既存のベストプラクティスに従います。
- ユーザーがページサイズを選べるようにするか、値を固定するかなど、ページングの方式を検討します。
- 希望どおりの実装を作成できるよう、プロンプトで必要なガイダンスを Copilot に伝えます。
- Copilot に変更を依頼し、コンテキストを与えながら何度かやりとりすることがあります。Copilot を使う通常のワークフローです。
